# 数据库课程设计固定答辩演示手册

本手册用于正式答辩、彩排和备用录屏。演示顺序、账号、金额与预期结果均与固定 Oracle 基线一致。正式演示前后都要执行演示数据恢复，不要临场修改价格、账号或步骤。

## 1. 演示目标与时长

主演示控制在 12 至 15 分钟，证明以下内容：

1. B/S 架构下 Vue 前端、ASP.NET Core .NET 10 五层后端和 Oracle 云数据库真实联动。
2. `WALLET_ACCOUNT` 是资金唯一真相，充值、购买、退款和市场交易均有独立账本。
3. DST 完成买断制购买、入库、评测、成就和退款闭环。
4. CS2 完成免费入库、库存实例、市场挂单、价格优先撮合、手续费、差额返还和物品流转闭环。
5. 好友、聊天、工坊、报价、资料、徽章、动态和讨论数据均由 Oracle 持久化，SignalR 提供实时通知。

## 3. 答辩前检查

总负责人提前 20 分钟完成以下检查：

1. 执行演示数据工具的 `reset`，记录本次运行编号；工具会先生成快照，再重置 42 张业务表并校验固定基线。
2. 访问 `/health` 和 `/health/database`，两者都必须返回 `OK`。
3. 打开商店页，确认首页先显示商店内容并在上层显示启动公告，而不是跳转到独立公告页。
4. 分别打开 CS2、DST 详情页，确认视频海报、5 张截图和全屏按钮可用；视频失败时静态海报仍应显示。
5. 准备两个独立浏览器上下文：主窗口用于玩家，隐私窗口用于管理员或 Bob，避免频繁退出登录。
6. 浏览器缩放保持 100%，关闭下载工具、弹窗拦截扩展和会覆盖页面的悬浮软件。

云服务器内执行恢复工具：

## 4. 主流程 A：新玩家、CS2 入库与 DST 交易闭环

### A1. 启动公告与注册，约 1 分钟

1. 打开商店首页。
2. 指出商店内容已经渲染，启动公告以浮窗覆盖其上；关闭公告。
3. 进入注册页，创建 `defense_demo`，昵称填写“答辩演示”，密码填写 `Demo123456`。

讲解词：

> 前端是 Vue 单页应用，所有业务数据都通过 ASP.NET Core API 访问腾讯云 Oracle。注册成功后后端同时创建玩家主体和钱包账户，前端不会保存业务真相。

预期结果：注册后自动登录并进入账户中心，角色为 `PLAYER`。

### A2. CS2 免费入库，约 1 分钟

1. 进入 CS2 商店详情。
2. 展示视频与截图画廊、市场概览、评价和成就摘要。
3. 点击“免费入库”，再点击“开始游戏”进入库内详情。

讲解词：

> CS2 采用免费领取模型。后端校验它是唯一允许免费领取的主演示游戏，并写入 `PLAYER_LIBRARY`；重复领取由唯一约束和业务规则共同阻止。

预期结果：页面提示“Counter-Strike 2 已免费入库”，游戏库出现 CS2，钱包余额仍为 ¥0.00。

### A3. 钱包充值与 DST 购买，约 2 分钟

1. 进入钱包，选择充值 ¥60.00。
2. 在结算页选择微信支付并确认。
3. 进入 DST 商店详情，展示媒体画廊和 -50% 折扣。
4. 点击“购买游戏”，选择 Steam 钱包支付并确认 ¥24.00。
5. 打开钱包消费历史。

讲解词：

> 资金唯一真相是 `WALLET_ACCOUNT.available_balance` 和 `frozen_balance`。充值与购买均在 Oracle 事务中更新余额、版本号和 `WALLET_TRANSACTION`，前端显示的是后端返回的账本结果。

预期结果：

- 充值后余额 ¥60.00。
- 购买后余额 ¥36.00。
- 历史中有 `+¥60.00` 充值和 `-¥24.00` 购买两行。
- 订单状态为 `COMPLETED / PAID`，DST 加入游戏库。

### A4. 游戏库、评测与成就，约 2 分钟

1. 打开游戏库，进入 DST 库内详情。
2. 进入“评价与成就”。
3. 选择“推荐”，填写“联机生存和创意工坊内容丰富，适合作为本课程的买断制游戏演示。”并发表。
4. 解锁 `First Night Together`。

讲解词：

> 发表评测和解锁成就前，后端都会再次检查当前玩家是否正常拥有游戏。评测显示的游戏时长直接来自 `PLAYER_LIBRARY.play_minutes`，不会由前端伪造。DST 成就是课程项目定义的演示成就，不宣称与 Steam 官方同步。

预期结果：

- 新评测显示“0.0 小时游戏时间记录”。
- 成就进度从 `0/6` 变为 `1/6`。
- 刷新页面后评测和成就仍存在。

### A5. 退款申请与管理员审核，约 2 分钟

1. 玩家进入“客服 / 退款申请”。
2. 选择刚购买的 DST 订单，保留默认退款理由并提交。
3. 在独立浏览器上下文以 `rootadmin / admin` 登录管理员。
4. 进入“管理 / 退款审核”，对最新 `PENDING` 退款点击“通过”。
5. 回到玩家窗口，刷新钱包消费历史和游戏库。

讲解词：

> 管理员审核在同一事务中更新退款单、订单、支付、明细退款金额、钱包、钱包流水和游戏库授权，并写退款审计日志。退款记录不会覆盖原购买记录，而是形成可追溯的正反两笔业务。

预期结果：

- 退款状态为 `APPROVED`。
- 钱包新增 `+¥24.00` 退款，余额回到 ¥60.00。
- 原订单显示 `CLOSED / REFUNDED`。
- DST 授权变为 `REVOKED`，游戏库只保留 CS2。

## 5. 主流程 B：CS2 库存、挂单、撮合与成交账本

此流程使用固定基线玩家。Alice 初始可用余额 ¥176.00；Bob 初始可用余额 ¥242.75、冻结余额 ¥50.00。Bob 的 ¥50.00 买单已经进入等待撮合状态。

### B1. 查看库存并现场挂单，约 2 分钟

1. 在主窗口以 `alice / alice` 登录。
2. 进入“库存 / CS2”。
3. 选择状态为 `NORMAL`、实例编号为 `ITEM_CS2_002` 的 `AK-47 | Redline`。
4. 点击“出售”，将价格从 ¥50.00 改为 **¥49.00**，确认出售。
5. 进入“社区市场 / 我的上架物品”，展示 ¥49.00 新卖单和 ¥50.00 基线卖单。

讲解词：

> 库存不是模板数量，而是带实例编号、磨损值、所有者和状态的实体。挂单事务会锁定实例并把状态从 `NORMAL` 改为 `IN_MARKET`，同一件饰品不能重复出售或同时用于交易报价。

预期结果：`ITEM_CS2_002` 状态变为 `IN_MARKET`；Alice 有 2 条等待撮合卖单，其中新卖单价格为 ¥49.00。

### B2. 执行撮合，约 1 分钟

1. 进入“市场交易记录”。
2. 点击“执行下一笔撮合”。
3. 展示最新成交行。

讲解词：

> 撮合按最低卖价、最高买价和创建时间排序。¥49.00 卖单优先匹配 Bob 的 ¥50.00 买单；成交价取卖价。Oracle 事务同时完成资金结算、订单状态、库存所有权、市场成交和资产流转账本。

预期结果：页面提示 `P001 → P002，成交价 ¥49.00`，最新成交物品为 `ITEM_CS2_002`。

### B3. 核对资金与资产，约 2 分钟

1. 打开 Alice 钱包，确认余额 ¥222.55。
2. 打开“物品流通”，查询 `ITEM_CS2_002`。
3. 在独立浏览器以 `bob / bob` 登录，查看钱包和库存。

讲解词：

> 平台费为 5%，¥49.00 的手续费是 ¥2.45，Alice 实收 ¥46.55，所以余额从 ¥176.00 变为 ¥222.55。Bob 原来冻结 ¥50.00，成交扣除 ¥49.00并退回 ¥1.00，因此可用余额变为 ¥243.75、冻结余额归零。

预期结果：

- Alice 可用余额 ¥222.55。
- Bob 可用余额 ¥243.75，冻结余额 ¥0.00。
- Bob 的 CS2 库存增加到 3 件并包含 `ITEM_CS2_002`。
- 流转账本新增 `TRADE P001 → P002`，历史 `DROP` 和先前交易仍保留。
- Alice 的 ¥50.00 基线卖单仍处于等待撮合，证明本次成交确实选择了更低的 ¥49.00 卖单。

## 6. 可选加分演示，约 2 至 4 分钟

时间允许时从以下项目选择一至两个，不要挤压两条主流程：

1. Alice 打开好友与聊天，向 Bob 发送消息；Bob 窗口无需刷新即可通过 SignalR 收到。
2. DST 社区切换工坊订阅，刷新后状态不丢失。
3. Alice 打开个人资料，展示背景、主题、等级、经验和精选徽章。
4. 打开交易报价，展示好友双方物品、锁定状态、接受、拒绝和撤销规则。
5. 在社区发布动态或讨论回复，展示 Oracle 持久化与实时通知。

## 7. 故障备用步骤

1. 页面无数据：先检查 `/health` 与 `/health/database`，不要连续点击提交按钮。
2. 临时账号已存在：说明上次数据未恢复，立即运行演示数据 `reset`，不要临场换账号造成脚本金额变化。
3. 订单或市场状态不符：运行 `reset` 后从该主流程开头重来；不要手工改 Oracle 表。
4. 视频加载慢：展示海报、截图切换和全屏功能后继续业务流程，媒体失败不影响 API。
5. SignalR 暂时断开：刷新页面后先确认“云端已连接”，聊天历史仍会从 Oracle 恢复。
6. 公网中断：播放答辩备用录屏，并用本地测试报告、数据库表结构和恢复审计记录继续讲解。
7. 错误操作后需要回滚：使用恢复工具输出的运行编号执行 `restore --run-id <运行编号> --confirm RESTORE-DEMO-DATA`，再做一次 `reset` 回到固定基线。

## 8. 答辩结束

1. 再执行一次演示数据 `reset`，保存最终运行编号。
2. 确认 API 与数据库健康检查通过。
3. 确认云端部署标记与 `main` 最新验收提交一致。
4. 不保留临时注册账号、评测、成就、退款、挂单、成交、聊天或社区帖子。
